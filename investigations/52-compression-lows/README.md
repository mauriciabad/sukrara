# Investigation 52: night compression lows

Standalone prototype for [docs/33](../../docs/33-compression-lows.md) (issue #52). Python 3.9 standard library only;
nothing here is part of Sukrara, and there is **no real health data**: every trace is generated by `traces.py`.

```
traces.py          synthetic nights with known truth: blood glucose, the sensor's lag, pressure on the sensor, what the
                   person does (turns over when the alarm wakes them, eats, logs it or not)
detector.py        the detector: a "suspect" at the fall, a "compression" label only after the rebound; never touches
                   an alert
evaluate.py        the tables in docs/33 (and --sweep: the rules on and off; --svg DIR: the example traces)
plot.py            the example traces as one SVG (docs/img/33/examples.svg)
test_detector.py   the detector's rules on hand-made traces
```

```sh
python3 -I investigations/52-compression-lows/test_detector.py
python3 -I investigations/52-compression-lows/evaluate.py            # ~1 min: 400 nights per kind, 1-min and 5-min readings
python3 -I investigations/52-compression-lows/evaluate.py --sweep    # ~3 min
python3 -I investigations/52-compression-lows/evaluate.py --svg docs/img/33
```

The numbers are only as good as the generator's assumptions (shapes and rates from the literature, behaviour made
up and stated in `traces.py`): they compare rules with each other, they don't measure real-world accuracy. Running
the detector over recorded nights is the follow-up's first step, on the owner's own exported CSV, locally, never
committed.
